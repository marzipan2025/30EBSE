# 30EBSE

기기에 있는 글을 **한 문장씩 한 페이지에** 보여 주는 e-ink 리더.
pdf · docx · txt · epub · md · srt 를 읽고, 구글 드라이브 앱이 깔려 있으면
**구글 문서도** 가져온다. Boox Poke4 Lite(e-ink)와 Nothing Phone (2a)를 두고 만들었다.

```
Android 11+ (minSdk 30)  ·  Kotlin + View/Canvas  ·  계정·로그인·추적 없음
```

29EBWO(개인용, 구글 드라이브 API + OAuth)에서 갈라져 나왔다. 구글 연동을 걷어 내고
**안드로이드 파일 선택창(SAF)** 으로 파일을 들이므로 심사나 API 키가 필요 없다.

## 설치

[Releases](https://github.com/marzipan2025/30EBSE/releases) 에서 APK 를 받아 설치한다.
Play 스토어에는 없다. 새 판이 나오면 앱이 알려 준다(아래 "앱 안 업데이트").

Boox 기기는 새로 설치한 앱을 자동으로 동결하므로, **설정 → 앱 → ❄ → `Automatically
enable freezing after installing an app`** 을 꺼 두는 편이 좋다.

## 파일 가져오기

목록 오른쪽 위의 `*` 를 누르면 시스템 파일 선택창이 뜬다. 여러 개를 한꺼번에 골라도 된다.

| 형식 | 가져오는 법 |
|---|---|
| **구글 문서** | 드라이브 앱이 PDF 로 내준 것을 PdfBox 로 글만 뽑는다 |
| pdf | PdfBox. 종이 폭에서 끊긴 줄은 도로 잇고 문단은 살린다 |
| docx | `word/document.xml` 의 문단(`w:p`)마다 글 토막(`w:t`)을 모은다 |
| txt | 인코딩을 알아맞힌다 — UTF-8·UTF-16·EUC-KR·MS949 … |
| md | 문법(`#` `**` 링크·그림·코드 표시)을 걷는다. 제목·목록 줄은 제 문단 |
| srt | 번호·시각을 걷고 대사만. 끝 부호나 1.5초 넘는 쉼에서 문단을 가른다 |
| epub | 글과 사진으로 풀어 둔다(아래 "epub") |

**원본을 붙들지 않는다.** 고른 순간 글로 풀어 앱 폴더에 두고 끝낸다(`Import`). 원본이
지워지거나 망이 끊겨도 읽을 수 있고, 저장소 권한도 들지 않는다. **같은 이름을 다시
고르면 같은 칸을 새 글로 바꾼다** — 읽던 자리는 그대로다. 원본을 고쳤으면 다시 고르면 된다.

**구글 드라이브** — 선택창 서랍에 드라이브가 뜨는 것은 **기기에 구글 드라이브 앱이 깔려
있을 때뿐이다**(드라이브 앱이 선택창에 문서 공급자를 붙인다). 없으면 기기 안의 파일만
보인다. 구글 문서는 기기에 바이트로 있는 파일이 아니라 "가상 파일" 이어서, 드라이브에
"이 꼴로 내 달라" 청해야 한다(`openTypedAssetFileDescriptor`). 드라이브가 구글 문서에
내주는 꼴은 **PDF 하나뿐**이다(22SUTO-A 에서 `getStreamTypes` 로 확인). 그래서 선택창에
`CATEGORY_OPENABLE` 을 붙이지 않는다 — 붙이면 가상 파일이 목록에서 빠진다. 종류로도
거르지 않는다(md·srt 는 대개 종류 없이 온다). 형식은 고른 뒤 확장자로 가린다.

**PDF 줄 잇기** — 줄 끝의 띄어쓰기는 PDF 를 만든 프로그램에 따라 남기도 사라지기도
한다(크롬이 뽑은 PDF 는 지운다 — 기기에서 실측). 그래서 기대지 않고 사이에 빈칸을 하나
둔다. 빈칸 없이 붙이는 것은 낱말을 쪼갠 붙임표(`inter-`/`national`)와 중국어·일본어
글자끼리뿐이다(`Import.joinWrapped`).

## 화면

**목록** — 스크롤이 없다. 화면 높이에 들어갈 만큼만 놓고 이전/다음으로 넘긴다.
칸마다 크기가 뜨고 `×` 로 지운다(Undo 가능).

**리더** — 한 쪽에 문장 하나. `"가자."` 도 `헉` 도 한 쪽을 다 쓴다.
화면을 셋으로 나눠 누른다.

```
┌─────────────────────────┐
│                         │
│   위 60%  ·  조작판 토글   │
│                         │
├─────┬───────────────────┤
│ 20% │   80%  ·  다음     │
│ 이전 │  (아래 40%)        │
└─────┴───────────────────┘
```

위 60% 는 어디를 눌러도 조작판을 켜고, 떠 있을 때 누르면 닫는다. 자리만 보고
글이 놓인 네모는 따지지 않는다 — 글은 화면 가운데라 대부분 위 60% 안에 들어,
읽다가 글을 짚어도 넘어가지 않는다. 조작판의 단추와 띠는 제 누름을 먼저 받는다.

다음으로 가는 자리를 넓게 둔다 — 읽는 동안 아홉 번은 다음이고 한 번이
이전이라, 자주 쓰는 쪽이 넓어야 보지 않고도 누른다.

문장 번호는 화면 15% 자리에 **늘 떠 있다**(조작판과 무관). 조작판은 좌우
위쪽의 `↰` 와 아래 18% 자리의 띠뿐이고, 5초 동안 조작이 없으면 시스템
막대와 함께 사라져 글만 남는다.
`↰` 는 먹의 바깥 끝을 글 상자(폭 60%)의 끝에 세운다 — 목록의 이름·`*` 와 같은 폭이다.

**목록** — 스크롤이 없다. 모든 것이 **활용공간**(화면 가운데, 폭 60% · 높이
80%) 안에 든다. 왼쪽 위에 이름과 `©`(앱 정보·라이선스), 오른쪽 위에 `*`, 아래 줄에
`←` 쪽번호 `→`. 칸마다 무게(MB, 소수점 한 자리, 단위 없음)와 `×` 를 단다. 새로 들인 것이
맨 앞이다.
리더처럼 시스템 막대를 걷고, 쓸어내릴 때만 잠깐 나오게 한다. **머리와 발은
리더의 줄에 선다** — 머리 가운데가 위에서 15%(문장 번호 줄), 발 가운데가
아래에서 15%(시계 줄). 두 화면을 오갈 때 위아래 줄이 제자리다(`Ink.EDGE_Y`).

글리프는 `Glyph` 가 **먹의 실제 자리를 재어** 네모 한가운데나 활용공간
가장자리에 맞춘다. 글자 상자 기준으로 두면 화살표가 치우쳐 보인다.

## 글이 놓이는 자리

글은 **화면 가운데 60% 상자** 안에만 놓이고 가로·세로 모두 가운데로 맞춘다.
17dp 에서 **한 줄 18자**, **한 쪽 최대 네 줄 75자**가 들어간다(실측).
넘는 문장은 쪼갠다 — 글자 크기를 줄이지는 않는다.

네 줄에서 끊는 것은 다섯 줄이 넘으면 한눈에 안 들어오기 때문이다. 대가가
있다: 실측한 문서(문장 1,064개)에서 **77%는 한 쪽에 오롯이 들어가고 나머지는
쪼개져** 1,274쪽이 된다. 상자를 넓히면 쪼개짐이 줄지만(90%에서는 0개) 한 줄이
24자로 길어진다 — 짧은 줄을 택한 값이다.

지렛대는 셋이고 모두 상수 하나다 — `Ink.MAX_LINES`, `Ink.TEXT_DP`,
`Ink.BOX_FRACTION`.

**짧은 꼬리는 앞 쪽에 붙인다.** 쪼갠 마지막 조각이 7자보다 짧으면(띄어쓰기·부호
포함, `있었다.` 따위) 앞 조각과 합쳐 다섯 줄 안에 들면 그 쪽만 다섯 줄로 둔다
(`PageBuilder.SHORT_TAIL`, `Ink.MAX_LINES_TAIL`). 한 쪽을 혼자 쓰기엔 허전하다.
미디어리터러시의혁명 64곳, 포도에서와인으로 67곳이 이렇게 붙었다.

## 문장 나누기

`Sentences` 가 문장으로 가르고, `PageBuilder` 가 들어가지 않는 문장만 쪼갠다.
쪼갤 때는 쉼표·닫는 따옴표처럼 뜻이 끊기는 자리를 먼저 쓴다.

자르지 않는 자리들 — 숫자 사이의 점(`3.14`), 날짜를 맺는 점
(`2026. 9. 12. 에`), 줄머리의 번호(`1. 첫째`), 줄임말(`Dr.`), 이름
머리글자(`J. R. R.`), 확장자(`ebse.kt`). 줄임표는 한 덩이로 본다.

**종이 폭에서 끊긴 줄은 도로 잇는다.** 옮겨 온 글에는 원본의
하드 줄바꿈이 그대로 들어 있는 일이 많다 — 실측한 한 문서(59,168자)는 빈 줄
아닌 줄 1,521개 가운데 **끝 부호로 끝나는 것이 23%뿐**이었다. 그걸 문장
경계로 세면 서른 몇 자짜리 토막이 한 쪽씩 차지한다. 이어붙이면 같은 문서가
1,521토막에서 **1,064문장(평균 55자)** 으로 돌아온다.

끊긴 자리에는 빈칸 하나를 둔다 — 그런 줄의 99%가 이미 빈칸으로 끝나 있었다.
다만 문단에서 가장 긴 줄의 60%보다 짧은 줄은 잇지 않는다. 끊긴 줄은 폭에
닿아 있으므로, 그보다 훨씬 짧으면 제목처럼 일부러 짧게 둔 줄이다.

**줄바꿈은 `WordWrap` 이 띄어쓰기에서만 한다.** 안드로이드에 맡기면 한글이
음절 단위로 아무 데서나 끊기고, 그걸 막는 `LineBreakConfig` 는 API 33 부터라
이 기기에서는 쓸 수 없다.

이 세 갈래는 안드로이드에 기대지 않는다. Android Studio 에 든 `kotlinc` 로
JVM 에서 그대로 시험한다.

```
kotlinc -include-runtime -d t.jar app/src/main/java/com/artbrain/ebse/text/*.kt Test.kt
```

## 글리프를 다루는 두 가지 함정

**가로는 `translationX` 로 옮기지 않는다.** 뷰를 옆으로 밀면 그만큼 반대쪽
여백이 잘려 글리프 끝이 날아간다. `wrap_content` 는 글자 폭(advance)에 딱
맞춰지는데 이탤릭 글리프의 먹은 그 폭을 넘어서므로, 밀면 바로 잘린다.
패딩을 줘도 translation 이 그걸 먹는다. 그래서 가로 가운데는 `match_parent`
＋ `gravity` 에 맡기고, `Glyph.centerVertical` 로 세로만 맞춘다.

가장자리에 세워야 하는 단추만 `Glyph.alignEdge` 로 먹의 끝을 재어 붙인다.
그러지 않으면 글리프가 활용공간 안쪽으로 들어가, 그 줄만 한쪽으로 쏠려 보인다.

**누름 표시는 `░` 다.** 기호도 `░` 도 같은 글꼴의 글자이므로 같은 크기·같은
자리에 겹쳐 놓으면 글자 뒤에 성긴 점무늬가 깔린 꼴이 된다(`Shade`). 네모를
칠하지 않는다 — e-ink 에서 면이 나타났다 사라지는 것은 요란하다.
**글자 수만큼 깐다** — `Undo` 면 `░░░░` 다. 고정폭이라 하나씩 포개진다.
목록 칸은 **제목이 끝난 자리부터 칸 오른쪽 끝까지** `░` 를 한 줄 친다(`LineShade`).
제목보다 1dp 작게, 기울이지 않은 Geist Mono 로 — 이탤릭으로 이으면 점무늬가
비스듬히 밀린다. 끝까지 채우려고 올림으로 세고 넘친 한 글자는 칸 경계에서 자른다.

**망이 없으면 시계 자리가 `Offline` 이 된다.** 누름 표시와 같은 셈으로 `▓` 를
글자 수만큼 깔고 흰 글자를 포갠다. 흰 글자는 가는 굵기로는 무늬에 묻히므로
Regular 로 올린다. 망이 붙거나 끊기는 순간 바로 바뀐다.

**알림은 모두 화면 한가운데 팝업이다**(`Popup`). 흰 면에 검은 테두리만 두른
네모. 아래쪽에 슬쩍 뜨는 토스트는 e-ink 에서 화면이 갱신되는 사이 이미 사라져
있기도 하다. 단추는 아래 한 줄에 두되 **닫기는 늘 오른쪽**, 되돌리기가 있으면
**왼쪽**이다.

**마지막 문장 팝업은 왼쪽에 `List` 를 둔다.** 끝까지 읽으면 갈 데는 목록뿐이라
조작판을 열어 `↰` 를 찾지 않아도 나가게 한다. 누를 틈을 주려고 되돌리기
팝업만큼(6초) 머문다.

**가는 굵기는 검게 보이지 않는다.** `wght 100` 은 획이 한 픽셀보다 얇아 모든
픽셀이 흰 바탕과 섞인 중간값이 된다 — 검게 지정해도 순수 검정 픽셀이 생기지
않는다(실측: 가장 어두운 값 48 이 한계). 검어야 하는 글자는 굵기를 올린다.

**오프라인은 사고가 아니다.** 전자책 기기는 대개 Wi-Fi 를 꺼 둔 채 쓰므로
"연결 안 됨" 이 보통 상태다. `Unable to resolve host ...` 를 그대로 띄우지
않고, 무엇이 문제이고 지금 무엇을 할 수 있는지를 말한다(`Net.explain`).

**지움은 되돌릴 수 있다.** 지울 때 파일을 없애지 않고 `files/trash/` 로
옮기고 읽던 자리도 남겨 둔다. 목록은 본문이 있는 칸만 보이므로 곧바로 빠지고, `Undo` 를
누르면 들인 차례의 제자리로 읽던 데까지 그대로 돌아온다. 팝업이 저절로 닫힐 때(6초)
비로소 정말 지우고, 앱을 다시 켤 때 남은 것을 쓸어 낸다.


## 회색은 하프톤으로

`Halftone` 이 4×4 베이어 무늬로 중간 밝기를 낸다. **무늬는 dp 가 아니라 화면
픽셀로 짠다** — dp 로 잡으면 212dpi 에서 1.325 배로 늘어나며 보간이 끼고 흐린
회색으로 뭉개진다. `isFilterBitmap` 과 앤티에일리어싱을 모두 끈다.

글자는 반대로 앤티에일리어싱을 켠다. 212dpi 에서 계단이 보이면 읽기 힘들다.

## e-ink 가 아닌 기기에서는 색을 뒤집는다

`Eink.isEink` — Onyx 의 `View.applyGCOnce()` 가 있는지로 가린다. 안드로이드에는
e-ink 화면을 알려 주는 표준 API 가 없고, 우리가 알고 싶은 것은 "전체 갱신을 걸 수
있는가" 이기 때문이다.

e-ink 가 아니면(발광 화면) **창 전체에 반전 필터를 한 겹 씌운다**(`applyTheme`,
하드웨어 레이어 + ColorMatrix). 바탕 `#000000` 에 흰 글씨가 되고, 옅기는 그대로
뒤집혀 유지된다. 화면마다 색을 고치지 않으므로 목록·리더·팝업·조작판이 한꺼번에
맞는다. epub 사진만 `photoFilter` 로 미리 한 번 뒤집어 원래 색으로 보인다. 전체
갱신은 부르지 않고 큰 시각만 띄운다. 파일 선택창은 우리 창이 아니라 뒤집히지
않는다.

Poke4 Lite 에서는 반전 전후 목록 스크린샷이 픽셀까지 같았다. 폰(1084px, 480dpi)
에서는 큰 시각 120dp 가 화면보다 넓어 좌우가 잘리는데, 그대로 둔다.

## 정각·15분마다 큰 시각과 전체 갱신

e-ink 는 빠른 부분 갱신만 거듭하면 잔상이 쌓인다. 전체 갱신(GC16)은 화면이 한 번
검게 깜빡이므로 아무 때나 할 수 없어서, **정각과 매 15분에 시각을 알리는 순간에
묶는다**(`Chime`). 목록과 리더가 같이 쓴다.

- 글자 뒤로 큰 시각을 **1.5초** 띄운다. Geist Mono Thin Italic 120dp, 옅기 0.35.
  루트의 맨 뒤 자식이라 글자·조작판·팝업이 모두 위에 오고, 누름을 먹지 않는다.
  그래서 `PageView` 는 바탕을 칠하지 않는다.
- 걷고 **0.1초 뒤** 전체 갱신을 건다. 0.2초만 띄웠더니 e-ink 가 글자를 찍기도
  전에 전체 갱신이 덮어 시각이 보이지 않았다. e-ink 가 아니면 갱신하지 않는다.
- 분이 바뀌는 신호 `ACTION_TIME_TICK` 을 받는다. Handler 로 15분을 재면 잠들었다
  깨거나 시계를 고쳤을 때 어긋난다. 20초 넘게 늦게 받은 신호는 넘긴다.
- 화면에 보일 때만 산다. 떠 있는 동안 다른 화면으로 가면 고치지 않고 걷는다.
  숨길 때 `GONE` 이 아니라 `INVISIBLE` — 목록이 레이아웃마다 칸 높이를 다시 센다.

**전체 갱신은 `View.applyGCOnce()` 하나만 열려 있다**(`Eink`). Onyx 프레임워크의
`ViewUpdateHelper.fullRefreshScreen`, `View.invalidate(int)` 은 일반 앱에
blacklist 로 막혀 있고, `VMRuntime.setHiddenApiExemptions` 우회도 막혔다.
기기 로그(`SDM update_to_display`)에서 평소 `waveform_mode=1 update_mode=0` 이
`waveform_mode=2 update_mode=1` 로 바뀌는 것으로 확인한다.

## epub

고른 파일을 앱 캐시로 옮긴 뒤 `Epub` 이 읽을 차례대로 글과 사진을 뽑고, `Fetch` 가
`docs/<id>.txt` 와 `docs/<id>/0001.png…` 로 저장한 다음 원본 사본은 지운다.
144MB 책이 글 0.5MB + 사진 10.5MB 가 되었다.
**차례(spine)를 따른다.** `linear="no"` 는 건너뛰되 표지는 남긴다.

**차례 쪽은 뺀다.** 모든 epub 에 공통된 표시가 없다. EPUB 3 의 `nav`, EPUB 2 의
`<guide type="toc">` 가 있으면 믿고, 없으면 **줄의 7할 이상(5줄 이상)이
toc.ncx·nav 제목과 똑같은 쪽**을 차례로 본다. 부분 일치로 재면 짧은 본문 장까지
걸렸다. 한국 출판사 책 둘은 차례 쪽에 아무 표시도 링크도 없어 이 셈으로만
걸러진다.

> 제목 견주기에 `\W` 를 쓰면 안 된다. JVM 정규식의 `\W` 는 ASCII 밖을 모두
> 낱말 아닌 글자로 봐서 한글 제목이 빈 문자열이 된다. `[^\p{L}\p{N}]` 로 쓴다.

**각주는 번호도 본문도 뺀다.** 번호만 빼면 장 끝에 모인 본문이 어디 붙는 말인지
알 수 없다. `epub:type`/`role` 의 footnote·endnote·noteref, class 에 `foot` 이
든 요소를 버린다. 위첨자는 `3` `[12]` `각주7` `*` 꼴일 때만 버리고 `m²` 는 둔다.

**사진은 한 쪽이다.** 사진 설명은 뒤따르는 글로 남아 제 문장이 된다. 책 안에서
두 번 넘게 쓰인 그림은 장식(소제목 무늬)으로 보고 뺀다. 가로·세로 모두 32px
아래인 그림도 버린다.

**사진은 글 상자 폭의 정사각형(454px)에 차게 맞춘다.** 작은 사진도 비율대로
키운다. 받을 때 맞춰 두고 리더는 늘리지 않고 한 픽셀씩 옮긴다.

**사진은 16단계 회색이다.** 베이어·오차 확산으로 점무늬를 내 보았더니 화면
격자와 어긋나 물결무늬가 섰다. 기기가 16단계 회색을 제대로 내므로 그 단계로
양자화해 둔다. 글자·조작판의 하프톤 원칙과 다른 것은 사진뿐이다.

본문에서 사진 쪽은 `￼0001.png`(U+FFFC + 파일 이름) 한 문단으로 적는다. 문장
가르기를 거쳐도 제 쪽 하나를 차지하고, 파일이 없으면 글로 그려진다.

XHTML 은 `Markup` 이 너그럽게 훑는다. epub 속 XHTML 에는 `&nbsp;` 같은 HTML
이름 문자가 선언 없이 들어 있어 엄격한 XML 파서는 거기서 멈춘다. `Markup` 과
`Epub` 은 순수 코틀린이라 JVM 에서 실제 책으로 시험할 수 있다.

**가져오는 동안 팝업에 퍼센트와 Cancel 을 둔다.** 파일을 옮겨 오기가 6할(구글 문서는
망을 탄다), 풀기가 4할이다. 숫자가 바뀔 때만 고쳐 쓴다.

## 글꼴

셋을 쓰고 **어느 것도 저장소에 넣지 않는다**(재배포하지 않으려고). 아래 자리에
두면 그대로 쓰이고, 없으면 기기 기본 글꼴로 물러난다 — `Fonts.of()` 가 이름으로
찾기 때문에 **글꼴이 하나도 없어도 빌드는 된다.** 이름으로 찾으므로 릴리스의 리소스
줄이기가 빼 버리지 않게 `res/raw/keep.xml` 로 붙들어 둔다.

```
app/src/main/res/font/a2z_regular.ttf        본문(한글). 에이투지체 Regular — OFL
app/src/main/res/font/geist_mono_italic.ttf  번호·화살표. Geist Mono Italic — OFL
app/src/main/res/font/geist_mono.ttf         제목. 기울이지 않은 Geist Mono — OFL
```

셋 다 SIL Open Font License 라 APK 에 넣어 배포해도 된다(글꼴만 따로 팔지 않는 한).
Geist Mono 는 가변 글꼴이라 `wght` 축을 100 으로 세워 Thin 으로 쓴다.

## 만들기

```
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell pm enable com.artbrain.ebse      # ← Boox 에서 빠뜨리면 안 된다
```

**Boox 는 새로 설치한 앱을 자동으로 동결한다**(`enabled=3`). `pm enable` 을
빠뜨리면 `Activity class does not exist` 로 보여 매니페스트 문제로 오해한다.

릴리스는 30EBSE 전용 키로 서명한다(`keystore.properties` + `keystore/`, 저장소 밖).
키가 없으면 서명 없는 APK 가 나온다. 키를 어디서 가져오는지는 `CLAUDE.md` 에.

PdfBox 가 데려오는 BouncyCastle 의 양자내성 암호 표(8MB)는 쓸 일이 없어 꾸릴 때
뺀다 — APK 가 8.3MB 에서 4.1MB 가 되었다.

## 앱 안 업데이트와 릴리스

`*` 를 누르면 선택창을 곧바로 열고, **뒤에서 하루에 한 번** GitHub 의 최신 릴리스
(`marzipan2025/30EBSE`, 태그 `vX.Y.Z` + `.apk` 첨부)를 본다(`Updater`). 새 판이 있으면
선택창을 덮지 않도록 **돌아온 뒤에** 묻는다 — 왼쪽 `Install`, 오른쪽 `Close`. 받는 동안
왼쪽에 퍼센트, 오른쪽에 `Cancel`, 다 받으면 시스템 설치 화면으로 넘긴다. 설치가 끝나면
그 화면의 "열기" 로 다시 연다.

- 공개 저장소라 토큰 없이 읽는다.
- 처음 한 번은 "출처를 알 수 없는 앱 설치" 권한이 필요하다. 없으면 팝업의
  `Settings` 로 설정 화면을 연다.
- **새 APK 는 깔린 것과 같은 키로 서명돼야 덮어 설치된다.** 릴리스 키 SHA-1
  `E8:2B:BB:4F:12:98:B6:17:FA:12:0D:4A:5C:5B:98:8E:93:8F:6E:1C`.

```
./gradlew :app:assembleRelease
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk | grep SHA-1
cp app/build/outputs/apk/release/app-release.apk /tmp/30EBSE-X.Y.Z.apk
git tag vX.Y.Z && git push origin vX.Y.Z
gh release create vX.Y.Z /tmp/30EBSE-X.Y.Z.apk -t "30EBSE X.Y.Z" -n "변경 요약"
```

**한 번 릴리스한 버전 번호는 다시 쓰지 않는다.** 앱은 GitHub 버전이 자기보다
높을 때만 알린다. 같은 번호로 APK 만 바꿔 올리면 먼저 받아 간 기기는 새것을
영영 받지 못한다(29EBWO 에서 겪었다).
